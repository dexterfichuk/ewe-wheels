    Engine CLI and protocol¶

    The Python and R packages are thin clients of ewe-engine, a small program that wraps EwE's computational core. Other languages and tools can use it directly.

    A small, stable facade over cCore for use from other languages and from the command line. It is new C# code on top of EwECore and leaves the maths untouched.

    ewe-engine run model.eiixml [--scenario N|NAME] [--years N] [--effort FLEET=MULT ...] [--out DIR]
ewe-engine info model.eiixml
ewe-engine serve                 # JSON lines over stdin/stdout (used by the Python and R SDKs)

    Build with dotnet build Sources/EwEEngine -c Release on Windows, macOS or Linux. Off Windows the net48 target of EwEUtils/EwECore is skipped automatically (Sources/Directory.Build.targets); on Windows pass -p:EwENet10Only=true to do the same.

    Protocol (version 1)¶

    One JSON object per line. Request {"id": 1, "method": "...", "params": {...}}, response {"id": 1, "result": ...} or {"id": 1, "error": {"message": "...", "type": "..."}}. On start the server prints {"ready": {...version...}}; send "shutdown" to stop.

    method params result
    version engine, EwECore, protocol, runtime and OS
    open path model info: name, sizes, groups, fleets, scenarios tables
    info same as open
    ecopath_inputs groups, diet (long), catch (by fleet) tables
    ecopath balanced, unbalanced_groups, groups table
    ecosim scenario, years, effort {fleet: multiplier}, vulnerability_multiplier, fleets groups and fleets (long, monthly), summary
    time_series scenario, dataset datasets table; with dataset, its series (long, yearly)
    fit scenario, dataset, vulnerabilities, anomaly_spline_points, anomaly_shape, reset_vulnerabilities (default false), max_iterations ss_before, ss_after (fresh reload with the fitted values), search_ss, aic, iterations, vulnerabilities (before/after per feeding link); with an anomaly search anomaly_shape and anomaly (month, year, value)
    fit_save fit {scenario, vulnerabilities [{predator, prey, vulnerability}], anomaly {shape, values}}, path, base, open writes the fit into the scenario; vulnerabilities_written, anomaly_shape, path, info if reopened
    fit_apply fit, base reloads the session with the fit applied (scratch file); info
    monte_carlo scenario, trials, seed, years, dataset trials (sum of squares), inputs (sampled Ecopath inputs), biomass (start/end per trial and group)
    ecotracer scenario, tracer_scenario, years concentrations (long, monthly; group (environment) is the environment)
    ecospace scenario, space_scenario, years, maps grid size, groups (map totals per time step), biomass_maps {group: rows x cols, null on land}
    mse scenario, trials, seed, years, parameters, groups, fleets, trial_values settings used, groups/fleets (biomass, catch, effort statistics over trials), value, yearly (mean and 5/50/95% per year), trial_values
    msy scenario, mode (group/fleet), target, max_rel_f, steps, trial_years, to_depletion curve (equilibrium biomass/catch per F, both assessments), optimum, baseline
    fmsy scenario, max_rel_f, steps, trial_years groups (FMSY, MSY, value per fished group and assessment)
    policy_search scenario, years, weights, parameters, groups, fleets, blocks, max_evaluations result (objective and its parts), blocks/effort (multipliers found), fleets, progress
    network_analysis summary (indicator, value, unit), ascendency (by source), groups (ascendency terms, keystoneness, PPR, L index, Psust), trophic_levels, decomposition, mixed_trophic_impacts (long)
    ecosim_network_analysis scenario, years, ppr indices: network indices per Ecosim time step (with ppr, also PPR, L index, Psust)
    indicators ecosim, scenario, years catalog, ecopath (indicator, category, value); with ecosim, ecosim (time step x indicator)
    model_export path (default: the open model) the model as a JSON model document
    model_validate model valid, errors, warnings (each {path, message})
    model_save model (optional), path, base (file or "template"; default the open model), open path, warnings, info if reopened
    model_apply model, base reloads the session on the edited model (scratch file); info, warnings
    model_schema JSON Schema of model documents
    close true

    Tables are columnar: {"columns": [...], "data": {"col": [...]}}. Missing values (NaN, EwE's -9999) are null. Groups and fleets are identified by name; index columns are EwE's 1-based indices. Ecosim overrides apply to one call only (the scenario is reloaded on every run), and so do fitted vulnerabilities and Monte Carlo samples until fit_save or fit_apply stores them. fit_save writes vulnerabilities to EcosimScenarioForcingMatrix and the anomaly to a forcing function (EcosimShape/EcosimShapeTime, default title "PP anomaly (fit)", updated in place when it exists) applied as a production rate multiplier to every producer (EcosimScenarioPredPreyShape). An anomaly search without anomaly_shape uses that shape, or adds it in memory for the run, since the .eiixml data source cannot add shapes itself.

    The management calls take EwE's own settings by name in snake_case (parameters, and groups / fleets keyed by name or 1-based index), for example {"parameters": {"regulatory_mode": "NoRegulations"}, "groups": {"Cod": {"fixed_f": 0.2}}}. Case and underscores are ignored, enum values go by name, an unknown name lists the known ones, and a value EwE's validation refuses is an error. Results echo the settings used, and every override is put back after the call.

    The module, management and analysis calls (time_series to indicators) also return messages: what the core reported while running, such as Ecospace warning about groups with too little habitat. In the desktop app these are pop-ups; headless, the core answers its own questions with the default and carries on, so check them when results look odd. Set EWE_ENGINE_LOG=1 to echo them to stderr as they happen.

    Network analysis and ecological indicators¶

    network_analysis, ecosim_network_analysis and indicators run the calculations of the Network Analysis and Ecological Indicators plug-ins (Sources/EwECustomPlugins). Those plug-ins are Windows Forms projects, so Sources/EwEEngine.NetworkAnalysis and Sources/EwEEngine.Indicators compile their calculation files (as links, unchanged) into plain .NET 10 libraries, with small shims for the status bar and user settings they touch. Settings keep the plug-ins' defaults; the optional cycle and pathway listing of the network analysis stays off. Every call reruns Ecopath, and the Ecosim variants reload and run the scenario like ecosim does. The Ecosim network analysis computes its indices at the end of every time step, as the plug-in does when "run with Ecosim" is on.

    Model documents (building and editing models)¶

    A model document ("format": "ewe-model", "version": 1) is the Ecopath part of a model as JSON: model metadata, groups, diet, detritus_fate, fleets, catch, discard_fate, stanzas and ecosim_scenarios, all keyed by name. The schema is in schema/ewe-model.schema.json (generated from ModelDocument.cs; ewe-engine schema regenerates it); ModelValidator adds the cross-checks (references, diet and fate sums, what Ecopath can estimate). Invalid documents fail with error type ModelValidationError and an errors list.

    Saving writes .eiixml onto a base file: the model the document came from (its Ecosim, Ecospace, Ecotracer, time series and other data are kept; rows the document does not touch are written back byte for byte) or Resources/template.eiixml, an empty model generated from EwECore/Resources/EwE6.mdb by python/tools/make_template.py together with column-defaults.json (the Access default of every column, used to fill new rows). Adding and removing groups, fleets and scenarios repeats cDBDataSource's bookkeeping (Ecosim and Ecospace copies of groups and fleets, fishing mortality shapes, cascading deletes). A field left out of an existing group keeps its stored value; JSON null means "not entered".

    CLI: ewe-engine export model.eiixml > doc.json, ewe-engine save doc.json out.eiixml [--base model.eiixml].

    Dispatcher.Handle(string) is the same entry point for in-process hosts such as pythonnet.

    Notes from bringing the engine to macOS and Linux¶

    • EwECore/EwEUtils build for net10.0 unchanged. Only the net48 target needed skipping off Windows.
    • cCore is not safe to construct concurrently within one process (a shared variable registry raises "Variable Index already registered"). Use one process per model for parallel runs.
    • lp_solve (MSE effort regulation) ships natives only for Windows and Linux x64. cLPSolverFactory falls back to the managed cManagedLPSolver elsewhere (EWE_LPSOLVER=managed forces it). Contract tests run against both solvers; a randomized cross-check compares them wherever native lp_solve loads.
    • WinForms in core is dead code only (#If 0, comments, an already-excluded file).
    • Ecospace, Monte Carlo, fit to time series and Ecotracer run unchanged on macOS and Linux (tested on macOS arm64 and Alpine Linux arm64/x64). The desktop app drives them through WinForms sync objects; the engine passes none (fit) or an inline ISynchronizeInvoke (Monte Carlo) and runs them on the calling thread.
    • MSE, MSY / FMSY and the fishing policy search run unchanged too. Their managers call the plug-in manager unguarded, so the engine's core gets an empty cPluginManager. MSE had no way to seed its trials and its quota calculator kept the random generator from construction, so even batch runs (fixed seed 42) did not repeat; cMSEDataStructures.RandomSeed and a quota calculator rebuilt per run fix both. MSY refuses to run while reference time series are enabled (the desktop app asks), so the engine switches them off for the run.
    • The .eiixml reader ignored Ecotracer scenarios ("not supported yet"), so Ecotracer could not run off Windows. It now reads them (read-only, like the rest of that data source). No shipped model has an Ecotracer scenario; python/tools/add_ecotracer_scenario.py builds the test fixture Sources/EwEEngine.Tests/TestData/anchovy-bay-ecotracer.eiixml.
    • Access .ewemdb reading uses OleDb (Windows only). python/src/ewe/convert.py converts them to .eiixml with mdbtools on any OS.

    Model documents¶

    Model documents (ModelDocument in Python, ewe_document() in R) follow a JSON Schema, available from ewe.model_schema() or ewe-engine schema.
