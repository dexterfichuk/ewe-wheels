    Opening models¶

    ewe.open ¶

    open(path: str | Path | ModelDocument, backend: str = 'process', engine: str | Path | None = None) -> Model

    Load an EwE model (.eiixml, or an Access .ewemdb/.mdb), or a ModelDocument.

    An Access database is converted to .eiixml first (with ewe-access, or mdbtools), so it can be edited and saved.

    Parameters:

    Name Type Description Default
    path str | Path | ModelDocument

    model file, or a ModelDocument to load without saving it.

    		 required
    backend str

    "process" (default; engine runs as a child process) or "inprocess" (pythonnet).

    		 'process'
    engine str | Path | None

    explicit path to ewe-engine(.dll); otherwise $EWE_ENGINE or a local build is used.

    		 None

    Load a :class:ModelDocument in a new engine session without saving it.

    document ¶

    document() -> 'ModelDocument'

    The model's groups, diet, fleets, catch and stanzas as an editable :class:ModelDocument.

    Apply edits with :meth:apply (to run them) or :meth:save. The document remembers this model's file, so saving it elsewhere keeps the model's Ecosim and Ecospace data.

    apply ¶

    apply(doc: 'ModelDocument') -> list[dict]

    Load doc into this session in place of the current model, on top of the current model's other data. Nothing is written to the original file; use :meth:save for that. Returns the validation warnings. Raises :class:ModelValidationError on errors.

    save ¶

    save(path: str | Path, doc: 'ModelDocument | None' = None, reopen: bool = True) -> Path

    Save the model: the current state, or doc applied on top of it.

    .eiixml by default; a .ewemdb/.mdb path writes an EwE Access database (via ewe-access).

    With reopen (default) this session continues on the saved .eiixml file. Saving to an Access database leaves the session as it was (the engine does not run on Access files).

    mse(trials: int = 10, scenario: int | str | None = None, seed: int | None = None, years: int | None = None, parameters: Settings | None = None, groups: Mapping[str | int, Settings] | None = None, fleets: Mapping[str | int, Settings] | None = None, trial_values: bool = False) -> MSEResult

    msy ¶

    msy(target: str | int | None = None, mode: str = 'group', scenario: int | str | None = None, max_rel_f: float | None = None, steps: int | None = None, trial_years: int | None = None, to_depletion: bool = False) -> MSYResult

    Equilibrium yield curves (EwE's MSY tool), under full compensation and a stationary system.

    Parameters:

    Name Type Description Default
    target str | int | None

    in group mode the group whose F is varied; in fleet mode the fleet whose effort is varied, or None for all fleets at once.

    		 None
    mode str

    "group" or "fleet".

    		 'group'
    max_rel_f float | None

    highest F to try as a multiple of the target's base F (group mode), or the highest effort multiplier (fleet mode). EwE's default is 5.

    		 None
    steps int | None

    number of equal F steps between 0 and the highest F.

    		 None
    trial_years int | None

    years Ecosim runs at each F to reach equilibrium.

    		 None
    to_depletion bool

    keep raising F until the catch is depleted instead of stopping at max_rel_f.

    		 False

    FMSY and MSY of every fished group (EwE's "Find FMSY"), one group at a time.

    policy_search ¶

    policy_search(scenario: int | str | None = None, years: int | None = None, weights: Settings | None = None, parameters: Settings | None = None, groups: Mapping[str | int, Settings] | None = None, fleets: Mapping[str | int, Settings] | None = None, blocks: Mapping[str | int, int | Sequence[int]] | None = None, max_evaluations: int | None = None) -> PolicySearchResult

    Search fleet effort multipliers that maximise a weighted objective (EwE's fishing policy search).

    Parameters:

    Name Type Description Default
    weights Settings | None

    objective weights, e.g. {"economic_weight": 1, "social_weight": 0, "mandated_rebuilding_weight": 0, "ecosystem_weight": 0.5, "biomass_diversity_weight": 0}.

    		 None
    parameters Settings | None

    search parameters, e.g. n_runs, init_option ("EcopathBaseF", "CurrentF", "RandomF"), search_option ("Fletch", "DFPmin"), discount_rate, base_year.

    		 None
    groups Mapping[str | int, Settings] | None

    group to objective settings, e.g. {"Cod": {"mand_rel_biom": 2}}.

    		 None
    fleets Mapping[str | int, Settings] | None

    fleet to objective settings, e.g. {"Trawlers": {"job_catch_value": 1.5}}.

    		 None
    blocks Mapping[str | int, int | Sequence[int]] | None

    fleet to its search block, one code for all years or one per year. Fleets sharing a code share one multiplier; 0 leaves a fleet out. Defaults to the model's blocks.

    		 None
    max_evaluations int | None

    cap on objective evaluations.

    		 None

    fit ¶

    fit(dataset: int | str, scenario: int | str | None = None, vulnerabilities: bool = True, anomaly_spline_points: int = 0, anomaly_shape: int | str | None = None, reset_vulnerabilities: bool = False, max_iterations: int | None = None) -> FitResult

    Fit Ecosim to a time series dataset (EwE's "Fit to time series" search).

    Nothing is stored in the model; pass the result to :meth:save_fit or :meth:apply_fit to keep it.

    Parameters:

    Name Type Description Default
    dataset int | str

    time series dataset, 1-based index or name (see :meth:time_series).

    		 required
    scenario int | str | None

    Ecosim scenario; defaults to the first.

    		 None
    vulnerabilities bool

    search vulnerabilities, one block per predator with reference data.

    		 True
    anomaly_spline_points int

    also search a primary production anomaly with this many spline points (1 = one value per year).

    		 0
    anomaly_shape int | str | None

    forcing function (1-based index or title) to hold the anomaly. By default a new one titled "PP anomaly (fit)" is used, or the existing one with that title. The shape is applied to the production rate of every producer.

    		 None
    reset_vulnerabilities bool

    start from EwE's default vulnerability (2), like the desktop app's "Use default v" option. Off by default, so the search refines the scenario's own vulnerabilities; on a model that was fitted before, a reset usually ends worse than it began.

    		 False

    The result keeps the best parameters the search tried (its last trial is sometimes worse). messages warns when the fit still scores worse than the scenario as stored. max_iterations: stop the search early.

    apply_fit ¶

    apply_fit(fit: FitResult, only_changed: bool = False) -> dict

    Load the model with fit's vulnerabilities and anomaly into this session, so later runs use them. Nothing is written to the original file; use :meth:save_fit for that.

    save_fit ¶

    save_fit(fit: FitResult, path: str | Path, reopen: bool = True, only_changed: bool = False) -> Path

    Save the model as .eiixml with fit's vulnerabilities and anomaly stored in its scenario.

    Vulnerabilities go where the EwE desktop app keeps them; the anomaly is a forcing function applied to the production rate of every producer. Forcing functions are shared by all scenarios of a model. With reopen (default) this session continues on the saved file.

    Parameters:

    Building and editing models¶

    ewe.authoring ¶

    Build and edit EwE models: the JSON model document.

    A :class:ModelDocument holds the Ecopath part of a model (groups, diet, fleets, catch, detritus and discard fates, multi-stanza groups) as plain data, keyed by name. Edit it with the methods below or with the DataFrame views, then save it as .eiixml, or open it in the engine to run Ecopath and Ecosim. The document format is described by the JSON Schema that ewe.model_schema() returns; the engine checks every document before writing it.

    doc = ewe.new_model("Toy bay", area=100) doc.add_group("Phytoplankton", "producer", biomass_area=15, pb=120) doc.add_group("Zooplankton", pb=30, qb=100, ee=0.9) doc.add_group("Detritus", "detritus", biomass_area=50) doc.set_diet("Zooplankton", {"Phytoplankton": 0.8, "Detritus": 0.2}) doc.save("toy.eiixml")

    Editing an existing model keeps everything the document does not cover (Ecosim, Ecospace and Ecotracer scenarios, time series, pedigree, ...):

    m = ewe.open("Tampa_Bay.eiixml") doc = m.document() doc.set_group("Pinfish", pb=2.5) m.apply(doc) # the open model now runs with the edit m.save("Tampa_Bay_edited.eiixml")

    Converting files¶

    ewe.convert ¶

    Convert EwE models between Access databases (.ewemdb / .mdb) and .eiixml without Windows.

    Two backends:

    • ewe-access (Sources/EwEAccess): Jackcess compiled to .NET with IKVM. Reads and writes Access databases; used automatically when it is built or bundled.
    • mdbtools: read-only fallback for :func:mdb_to_eiixml.

    EwE's .eiixml format is a plain dump of the Access tables (see cEIIXMLDataSource.SaveFromDB in EwECore): one

    per table and one comma-separated per record. Writing that same format from mdbtools (https://github.com/mdbtools/mdbtools) gives a model that loads on any OS.

    Requires the mdbtools command line tools (brew install mdbtools / apt install mdbtools).

    Plotting¶

    ewe.plot ¶

    Plots of SDK results with matplotlib (pip install ewe[plot]).

    Every result has a plot accessor, so the usual charts are one call away::

    sim = m.ecosim()
sim.plot()                          # biomass over time, one line per group
sim.plot.biomass(relative=True)     # relative to the first year
sim.plot.catch(groups=["Cod", "Anchovy"])
sim.plot.fleets()                   # landings by fleet, stacked
m.time_series(2).plot.fit(sim)      # observed vs predicted
m.msy("Anchovy").plot()             # yield curve
m.ecospace().plot.map("Cod")
m.plot.foodweb()                    # Ecopath flow diagram by trophic level

    The functions behind the accessors live here too (ewe.plot.ecosim(sim), ewe.plot.compare(...)) and take the same arguments. Each returns the matplotlib Axes it drew on, or an array of Axes when the chart is split into small multiples, so it can be restyled or saved with the usual matplotlib calls. The data behind every chart stays available as DataFrames on the result.

    Colours are taken in a fixed order (validated so neighbouring colours stay apart for colour-blind readers), in the order the series are shown; pass groups= in the same order to keep a group's colour from chart to chart. More than eight series never share one set of axes: the chart becomes small multiples, or the smallest series fold into "Other". set_theme("dark") switches every chart to the dark palette.
